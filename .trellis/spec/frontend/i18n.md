# Frontend i18n Contract

> `i18next` + `react-i18next` locale packs under `src/locales/{zh-CN,en}/`.

---

## 1. Scope / Trigger

- Applies to all new user-visible UI strings on the React side
- Does **not** require translating every Rust `Err(String)` in the same PR (map when wording is stable)
- Deep dialog / git / dense settings leftovers may be deferred only with an explicit leftovers tracker

## 2. Signatures

| API | Location | Behavior |
|-----|----------|----------|
| `changeAppLocale(locale)` | `src/lib/i18n/index.ts` | `i18n.changeLanguage` + persist |
| `getStoredLocale()` / bootstrap | `src/lib/i18n/locale.ts` | read `localStorage['codex-ai:locale']`; default `zh-CN` |
| `useTranslation(ns?)` | components | preferred in React trees |
| `i18n.t('ns:key')` | pure helpers (`utils.ts`) | for non-hook call sites |
| `getActivityActionLabel(key)` | `src/lib/utils.ts` | **only** via `activity:actions.*` — no parallel Chinese map |
| `getStatusLabel` / `getPriorityLabel` | `src/lib/utils.ts` | display paths must use these, not `TASK_STATUSES.label` / `PRIORITIES.label` |
| `mapBackendError(message)` | `src/lib/i18n/mapBackendError.ts` | passthrough unless a stable phrase→key map exists |

Supported locales: `zh-CN` | `en`.

Namespaces (JSON files mirror names): `common`, `nav`, `activity`, `settings`, `errors`, `ssh`, `dashboard`, `kanban`, `sessions`, `employees`, `projects`, `trash`, `notifications`.

## 3. Contracts

- Bootstrap: wrap app with `I18nextProvider` in `src/main.tsx`
- Persistence key: `codex-ai:locale` (restart-safe)
- Default locale: `zh-CN` (must match prior Chinese UX for migrated strings)
- Settings switch: Runtime / 界面与运行 language control calls `changeAppLocale`
- Activity labels: single source in `src/locales/*/activity.json` under `actions`
- Date display: still prefer `formatDate()`; localeCompare uses active locale where sorting is user-visible
- Do not call `invoke` from i18n layer; IPC stays in `backend.ts`

## 4. Validation & Error Matrix

| Case | Behavior |
|------|----------|
| Missing locale key | i18next default (key/fallback); do not crash |
| Invalid stored locale | fall back to `zh-CN` |
| Backend Chinese error | show passthrough unless mapped |
| Unmigrated dialog still using `.label` | may remain Chinese in `en` — track in leftovers |

## 5. Good / Base / Bad Cases

- **Good**: new toast uses `t('common:saved')` with zh-CN + en entries
- **Base**: switch to `en`, reload app, Sidebar/Header stay English
- **Bad**: reintroduce a hardcoded Chinese map beside `getActivityActionLabel`; add UI string only in one locale pack

## 6. Tests Required

| Assertion | Location |
|-----------|----------|
| Locale persist / change helpers | `src/lib/i18n/locale.test.ts` |
| Activity/status helpers still resolve | existing utils/store tests + locale tests |
| Gates | `npm run format:check`, `npm run test:ci`, `npm run build` |

## 7. Wrong vs Correct

| Wrong | Correct |
|-------|---------|
| `TASK_STATUSES.find(...).label` in UI | `getStatusLabel(status)` |
| Duplicate `ACTIVITY_LABELS` Record in utils | `i18n.t('activity:actions.' + key)` |
| Hardcode English only in component | add both `zh-CN` and `en` JSON keys |
| Claim I2 complete while nav still Chinese in `en` | main-path chrome must be extracted; deep dialogs → leftovers |
