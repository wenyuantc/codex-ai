# PRD · B1 并发闸门与运行队列

父任务:`08-12-product-gap-wave` · 优先级 N-P0

## 需求

1. **全局并发上限**:同时运行的 AI 会话进程数有全局闸门,设置页可配(默认 2–3),四引擎共用一个计数(挂在 `engine/` 共享内核)。
2. **运行队列**:超出上限的任务启动请求进入队列排队,不失败、不裸并发;进程结束自动放行队首。
3. **队列持久化**:排队状态存 SQLite,应用重启后队列恢复(参照 `task_automation_state` 的 resume 模式)。
4. **看板可见**:排队中的任务卡片显示「排队中(第 N 位)」;可取消排队。
5. **批量运行**:看板支持选中多个任务批量入队运行(复用 `batch_update_tasks` 的选中机制)。

## 约束

- 闸门在共享内核收口,不在四个引擎各写一份(CLAUDE.md 既定原则:先改共享内核)。
- 协调员编排、自动化审查等内部启动的会话同样受闸门约束(或明确豁免并说明理由)。
- SSH 会话计入同一全局并发计数。

## 验收标准

- [ ] 并发上限可在设置页配置并持久化;默认值 2–3。
- [ ] 超限启动进入队列;先入先出;进程退出后队首自动启动。
- [ ] 重启应用后队列不丢(数据库可查、UI 恢复显示)。
- [ ] 看板卡片显示排队位次,可取消;i18n zh/en 齐全;写活动日志。
- [ ] 批量运行选中任务可用。
- [ ] Rust 单元测试覆盖:闸门计数、入队/出队/取消、重启恢复。
