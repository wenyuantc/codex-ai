# 看板新建任务支持创建并执行

## Goal

在看板「新建任务」弹窗提供「创建并执行」：创建成功后自动启动执行。有协调员时默认后台生成协调员计划并注入执行（不弹确认框）；无协调员则直接执行。降低「写完就跑」的操作成本，同时保留卡片/详情上的人工确认计划路径。

## Background

### 现状（仓库事实）

- `CreateTaskDialog` 仅创建任务（含标签、依赖、附件），无执行入口。  
  `src/components/tasks/CreateTaskDialog.tsx`
- 卡片/详情「运行」：有 `coordinator_id` → `CoordinatorPlanDialog` 确认后再 `runTask(plan)`；无协调员 → 直接 `runTask()`。  
  `src/components/tasks/TaskCard.tsx`、`TaskDetailDialog.tsx`
- 执行必须有 `assignee_id`，否则报错「请先指定执行员工」。  
  `src/components/tasks/hooks/useTaskExecutionActions.ts`
- 协调员计划：`aiGenerateCoordinatorTaskPlan` → `ai_generate_coordinator_task_plan`；落库字段 `tasks.plan_content`。
- 创建校验：标题/项目必填；默认自动质控开启时必须审查员；支持 worktree / SSH 项目。
- 活动 key 已有 `task_created`、`task_coordinator_changed`、`task_plan_saved` 等中文标签（`src/lib/utils.ts`）。
- 前端无通用 toast；任务日志由 `KanbanBoard` 的 `TaskLogDialog` + `onOpenLog` 承载。

### 已确认产品决策

| 决策 | 选择 |
|---|---|
| 交互形态 | 方案 A：双按钮「创建」+「创建并执行」 |
| 有协调员默认策略 | 后台生成计划 → 自动执行（不弹确认框） |
| MVP 是否做「自动/确认」开关 | **否（选项 A）**；需要审计划时用「创建」+ 卡片运行 |
| 计划生成失败 | 保留已创建任务，不跳过计划直接执行，明确报错 |
| 队列/启动模式枚举 | 不在本任务范围 |

## Requirements

### R1. 新建任务弹窗双提交

- 保留「创建」：仅创建，不执行。
- 新增主 CTA「创建并执行」。
- 校验失败、defaults 加载中、提交流程进行中时，两个按钮均不可重复提交。

### R2. 创建并执行 — 无协调员

- 完成与「创建」相同的落库与后处理（标签、依赖、附件）。
- 创建成功后立即按现有执行管线启动（worktree 准备、SSH/本地工作目录、引擎、状态/计时/任务日志）。
- 启动成功后关闭弹窗；看板任务可见运行态；尽量自动打开该任务执行日志。

### R3. 创建并执行 — 有协调员（固定自动策略）

- 创建成功后 **不** 打开 `CoordinatorPlanDialog`。
- 后台生成协调员计划 → 写入 `plan_content` → 以该计划作为执行输入启动（对齐 `runTask(plan)`）。
- 用户可在任务详情查看 `plan_content`。
- 提交过程中弹窗内展示阶段文案（创建中 / 生成计划中 / 启动执行中）；禁止无反馈静默失败。

### R4. 前置校验（创建并执行，创建前拦截）

- 标题、项目必填（与创建一致）。
- **必须指定执行员工**。
- 默认自动质控开启时必须指定审查员。
- defaults 仍在加载时不可提交。

### R5. 协调员计划失败

- 任务若已创建成功：保留任务，**不**自动跳过计划直接执行。
- 弹窗内明确错误（可关闭后到看板用现有「运行」/协调员计划流重试）。
- 不回滚删除已创建任务。

### R6. 复用与一致性

- 不在 `CreateTaskDialog` 内复制引擎启动细节；抽取/复用与卡片等价的执行启动能力。
- 本地/SSH、worktree、附件图片带入执行与看板运行一致。
- 活动日志中文完整；缺标签则补齐。

### R7. 回归保护

- 卡片/详情「运行」有协调员时仍走确认计划弹窗（含已有 plan 的现有行为）。
- 仅「创建」不触发执行。

## Acceptance Criteria

- [ ] AC1：弹窗可见「创建」与「创建并执行」；仅「创建」不启动会话。
- [ ] AC2：无协调员 + 已指派执行人 +「创建并执行」→ 任务创建并进入执行中。
- [ ] AC3：有协调员 + 已指派执行人 +「创建并执行」→ 不弹协调员确认框，自动生成 `plan_content` 并启动执行。
- [ ] AC4：未指派执行人点「创建并执行」→ 不创建任务，并提示需指定执行员工。
- [ ] AC5：协调员计划生成失败 → 任务保留、未启动执行、弹窗有明确错误。
- [ ] AC6：SSH 与 worktree 路径与卡片运行行为一致。
- [ ] AC7：卡片/详情原协调员确认执行流正常。
- [ ] AC8：相关活动在仪表盘显示中文（无裸 key）。

## Out of Scope

- 创建弹窗内「协调员：自动执行 | 确认后执行」开关或设置页持久化策略。
- 「创建并自动质控」独立按钮（任务级 automation 已有）。
- 全局执行队列 / 多任务排队调度。
- 协调员角色定义或计划提示词内容改动。
- 测试员验收清单联动。

## Risks

- 创建 → plan → run 是多步异步：应用同一 `saving`/阶段锁，避免双击与竞态。
- 计划质量差时会直接空跑：接受为 MVP 代价；卡片确认流仍可用。
- 弹窗关闭时机：建议 **整条链路成功后再关**，避免卸载中断与无 toast 时的反馈丢失。
