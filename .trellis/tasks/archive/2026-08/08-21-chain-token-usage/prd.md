# PRD · 执行链路显示会话用量

> 来源：用户 2026-08-21 任务详情截图；红箭头指向「执行链路」会话卡片右侧空白。
> 轻量任务：仅前端展示，不改 schema / IPC。

## Goal

任务详情「执行链路」里，每个会话卡片直接显示该会话的 token 用量：输入、输出、缓存、总用量、缓存率。侧栏任务级「用量」补上「缓存」字段，五项口径与顺序一致。

## 已锁定决策

| 决策 | 选择 |
|---|---|
| 数据源 | 已有 `listCodexSessions` 的 session token 字段 + 侧栏已有 `get_task_token_usage` |
| 无值 | 显示「未知」，不假装 0 |
| 金额 | 不做换算（沿用一期 token-only） |
| 会话页 | 对话管理卡片 + 表格同样展示五项，含缓存与缓存率 |
| 刷新 | 走执行链路现有「刷新」；不加轮询 |

## Requirements

- R1 执行链路每个会话卡片展示五项：输入、输出、缓存、总用量、缓存率。
- R2 字段顺序固定为：输入 → 输出 → 缓存 → 总用量 → 缓存率。
- R3 某字段为 `null` 时显示未知；缓存率为空分母时显示「—」。
- R4 任务详情侧栏用量组补「缓存」并采用同一顺序；无会话上报时整组仍显示，值为未知。
- R5 文案走 i18n（zh-CN + en）；数字格式复用 `formatTokenCount`，缓存率复用 `resolveCacheRateDisplay`。
- R6 本地与 SSH 会话同一套展示，不新增命令或迁移。
- R7 对话管理（卡片 + 表格）同样展示缓存用量与缓存率，复用 `TokenUsageBreakdown` / `buildTokenUsageMetrics`。

## Acceptance Criteria

- 打开有用量会话的任务详情 → 执行链路：卡片上可见五项数字（或未知）。
- 无用量会话：五项均为「未知」，不出现 `0` / `0.0%`。
- 侧栏用量组含缓存，顺序与执行链路一致。
- 对话管理卡片与表格可见缓存用量、缓存率；无值显示未知，不假装 0。
- `npm run test:ci` 覆盖展示推导（未知 / 已知拆分 / 缓存率）。
- `npm run format:check` 通过。

## Out of Scope

- Token → 金额
- 会话列表筛选/排序按缓存率
- 执行中实时推送用量
- 新建任务弹窗（新任务无用量）
