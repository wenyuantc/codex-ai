# 看板交付 UX 与可发现性

## Goal

让里程碑、标签、依赖、批量改状态、筛选、归档管理在看板上 **可发现、可操作、文案中文**，消除「后端有、前端不好用」的交付能力断层。

## Background

- Delivery（标签/依赖/里程碑）后端 + 部分 UI 已存在（migration 40 + `app/delivery.rs`）。
- `TASK.md` 未完成：筛选选择后显示英文；归档管理可看详情不可编辑。
- 批量改状态 UI 已有基础（`KanbanPage`）。

## Requirements

### R1 筛选与批量

- 看板筛选：项目、状态、优先级、标签、里程碑、执行人等；**所有选项展示中文**（不露出 raw enum 给用户）。
- 批量修改状态：选中后操作反馈中文；写 activity。

### R2 里程碑 / 标签 / 依赖可发现

- 任务卡与任务详情 Overview 明确展示标签、里程碑、依赖摘要。
- 创建/编辑任务可维护上述字段（复用现有 command，补齐入口）。

### R3 归档管理

- 归档列表可打开任务详情。
- 在合理范围内支持编辑（至少标题/描述/标签/优先级；状态取消归档等与现有归档规则一致）。
- 永久删除保持二次确认。

### R4 兼容

- SSH 模式筛选仅 SSH 项目；本地同理。
- 时间字段 `formatDate()`。

## Acceptance Criteria

- [ ] 筛选下拉无英文 raw 值暴露
- [ ] 任务卡可见标签/里程碑（有则显示）
- [ ] 归档管理可编辑关键字段并保存成功
- [ ] 批量改状态成功且活动中文
- [ ] `npm run build` 通过

## Out of Scope

- 全新甘特图
- 跨项目依赖图可视化（可后续）
